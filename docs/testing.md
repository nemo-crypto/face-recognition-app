# 验收与测试边界

## 自动化

- `npm run build`：严格 TypeScript 检查与生产构建。
- `go test -race ./...`：API 完整流程、授权/来源检查、请求体限制、图片格式、持久化失败、并发写入、人员删除竞态、模型判定及失败处理、记录保留上限。
- `go vet ./...`：Go 静态检查。
- `npm run test:e2e`：真实 Go 后端与 Chromium 浏览器；桌面、移动模拟的登记/核验/筛选/删除、相机权限错误、网络错误和多宽度布局。

浏览器测试在系统临时目录创建独立数据目录，使用生成的示例图，不连接真实模型、不上传真人照片。测试截图及失败 trace 在 test-results，默认不提交。

## 真机待验收项

1. iOS Safari / Android Chrome 在可信 HTTPS 上申请相机权限、切换镜头、拍照及释放轨道。
2. 前台/后台切换、横竖屏和设备内存压力下的恢复行为。
3. 实际模型 endpoint 的协议、时延、错误及参考图有效性处理。
4. 模型阈值、活体机制、误识/拒识情况；不得把 mock 或静态照片测试当真实身份验证证据。
5. 部署环境的 token、TLS、目录权限、备份恢复及删除传播。
